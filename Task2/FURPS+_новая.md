## FURPS+

```

Функциональные (Functionality, F) — то, что система должна выполнять на релизе. Такой пример мы описывали выше.

Удобство использования (Usability, U) — правила, по которым система взаимодействует с пользователем. Это могут быть UX/UI-дизайн, правила работы интерфейса для людей с ограниченными возможностями, справочная информация по работе с системой.

Надёжность (Reliability, R) — всё, что относится к работоспособности системы: время простоя в случае сбоя, режим работы, график обслуживания. Обычно невозможно сделать систему устойчивой в любой ситуации, поэтому сразу важно заложить ограничения.

Производительность (Performance, P) — всё, что относится к быстродействию и потреблению ресурсов: время отклика, масштабирование системы, число одновременных пользователей.

Поддерживаемость (Supportability, S) — возможность и правила тестирования, параметры  расширения и доработки системы.

Ограничения (остальное со знаком +) — это дополнительные ограничения, которые мы накладываем на систему: языки программирования, правила проектирования, применение определённых баз данных. Эту группу можно отнести к архитектурно значимым требованиям, о которых мы поговорим позже.
```

|     | Клиент может подать заявку на депозит, заполнив свой номер телефона и Ф.И.О. |              |
|     | Заявка с сайта создается в CRM-системе кол-центра. |              |
|     | Менеджер кол-центра должен обработать заявкy клиента. |              |
|     | Менеджер кол-центра может предложить специальные ставки. |              |
|     | Менеджер фронт-офиса должен подтвердить идентификацию пользователя. |              |
|     | Менеджер фронт-офиса создаёт депозит и выдаёт клиенту необходимые документы. |              |
|     | Менеджер фронт-офиса загружает документы в систему депозитов.  |              |
|     | 
|     | В интернет-банке клиента отображается список доступных депозитов с актуальными ставками и персонализированные ставки. |              |
|     | Клиент может подать заявку на открытие депозита, указав счёт и сумму депозита.  |              |
|     | Клиент должен подтвердить операцию открытия депозита с помощью СМС-кода. |              |
|     | Mенеджер в бэк-офисе должен обработать заявку на открытие депозита в АБС банка. |              |
|     | Клиент должен получить СМС-уведомления после подтверждения размера ставки и открытия депозита. |              |
|     | ...                                |              |
| U   | Удобство использования (Usability) |              |
|     | Интерфейс должен быть удобным для клиента. |              |
|     | При разработке интерфейса приложения использовать дизайн, который принят в компании. |              |
|     | ...                                |              |
| R   | Надёжность (Reliability)           |              |
|     | Все сервисы должны работать 24/7 и быть доступны в 99,9% случаев  (Разработка и согласование SLA, SLO) |              |
|     | В случае сбоев в ЦОД необходимо, чтобы сервисы интернет-банка были доступны и выдерживали требуемую нагрузку. |              |
|     | Использовать резервный ЦОД |              |
|     | ...                                |              |
| P   | Производительность (Performance)   |              |
|     | Отклик по всем операциям должен занимать миллисекунды.  (Согласовать значение 95% персентиля) |              |
|     | ...                                |              |
| S   | Поддерживаемость (Supportability)  |              |
|     | Необходимо предусмотреть разработку документации для дальнейшего расширения системы. |              |
|     | Рассмотреть вариант о переводе интернет-банка на микросервисную архитектуру, в рамках задачи открытия депозитов. |              |
|     | ...                                |              |
| +R  | + Ограничения (Restrictions)       |              |
|     | Идентификация происходит в отделение банка. |              |
|     | Данные передаваемые с сайта необходимо защитить с помощью механизма шифрования.  |              |
|     | Данные при передаче в интернет-банке необходимо защитить с помощью механизмом шифрования. |              |
|     | Ставки по депозитам ведутся в XLS-файлах. С ними должны иметь возможность работать сотрудники бэк-офиса депозитов и бэк-офиса кредитов. (Архитектурное ограничение) |              |

|     | Если нужны очереди сообщений, то нужно использовать Kafka. Но текущая версия платформы интернет-банка несовместима с ней. |              |
